## Delivery architecture

- Workstream A uses an additive authenticated Observatory API successor and strictly typed trace responses. Diagnostic reconstruction calls the existing gap controller, resampler, filter, windowing/quality, and normalization code; no JavaScript scientific implementation. One explicitly armed, owner-scoped pre-start capture installs instance-local delegating observers before the first batch, retaining only the selected source/gap/resampler/filter interval in memory. Captured and reconstructed outputs are separately classified. The arm action changes only transient observability state; opening a trace never starts inference. Capture capacity is two, TTL one hour, and response size at most 750 kB. A historical session may attach persisted inference metadata only after owner, frozen scenario seed, source timestamp and quality checks. A prior session without an armed capture is never relabelled live-captured.
- Workstream B derives client/round presentation from the real cohort manifest and owner-scoped run/checkpoint metadata; the existing Federation Studio remains the event-journal view. The selected-client signal inspector delegates to the same canonical streaming operators as Workstream A and uses `WEARABLE_SIM_EVENT_WINDOW_V1` only for eligible windows. It never treats a `SUBMITTED` UI state alone as proof of coordinator acceptance. All eight clients are logical synthetic clients on one machine. Contribution weight is based on accepted `examples_seen`, not frozen roster percentages or accuracy. The all-round matrix distinguishes `DIRECT_COORDINATOR_MAP`, `GOVERNANCE_ATTESTED_SERVER_JOURNAL`, and `NOT_RECORDED`; the last is fail-closed for missing or inconsistent final-round evidence.
- Workstream C reads frozen scientific evidence and authorized record views only. Its current record endpoint enforces the TRAIN split and verifies frozen manifest, cache and example-ID hashes before serving one processed waveform; raw beat positions are unavailable because raw WFDB bytes are not in this checkout. No held-out inference, new efficacy experiment, calibration fitting, checkpoint promotion, or synthetic-label candidate efficacy is in scope. Connected Clerk is primary when credentials are available; the offline DEMO path remains an explicit contingency.

## Non-negotiable boundaries

`MODEL_V2_FINAL` is centrally trained and remains the monitoring default inside `SOFTWARE_SYSTEM_V2`. FL starts from `FL_INIT_V2` and creates sandbox-only engineering candidates. `AAMI_SVF_WINDOW_V1` scientific labels and `WEARABLE_SIM_EVENT_WINDOW_V1` synthetic engineering labels are different targets. `MODEL_V2_NOT_PROMOTED_RELEASE_CI` and `SYSTEM_V2_RESEARCH_DEFAULT_ACCEPTED` remain distinct decisions. `CAL_V2` is MIT-BIH source-domain only; SecAgg supports `PROTECTED_AGGREGATION_INTERFACE_ONLY`. No hardware, clinical, patient-specific, DP, anonymity, or hospital claim is introduced.

The normal FL update envelope carries no raw ECG training tensor. The Observatory's bounded synthetic signal response is a **separate authenticated read-only inspection data flow**, not part of the normal FL update protocol. The original v1.9 UI lock, old scientific reports, and protected runtime/FL algorithms remain byte-identical.
